# Testing instructions — Platea (XPRIZE Build with Gemini)

> Everything below is free and accessible to judges through the end of the Judging Period
> (15 Sep 2026), no credentials required. Nothing here touches live ticket sales.

## 1. See the live product a customer actually uses (2 min)

- Box office site: **https://elgorilateatro.com.mx** — this is the real, currently-selling
  checkout for *El Gorila*, Season 2 (Teatro Wilberto Cantón, Mexico City, Saturdays through
  19 Sep 2026). Buying a ticket here is a real Stripe transaction; you don't need to buy one to
  verify it's real — the seat count and prices move live.
- WhatsApp: message the production's customer number and ask a question about showtimes, prices,
  or the couple discount ("ESPEJO"). The reply is generated by a Gemini agent (Vertex AI) reading
  the production's live data, not a canned script. A human (the founder) only gets involved if
  the bot escalates.

## 2. See the AI agents that run the business (5 min)

- Repo: **https://github.com/dupeyronosterlen/platea** — read `01_Agentes/*/persona.md` and
  `playbook.md` for each agent's role, and `*/agent.py` for the code that actually runs on a
  schedule (Media Buyer, Boletera Sync, Analytics/Funnel).
- `09_XPRIZE/ai-decisions.md` — five concrete instances of the AI making a real operating call
  from live data (an ad-spend bug it found and fixed itself, a funnel leak diagnosis, a CPA
  correction, a bot root-cause fix, a budget-escalation clock), each tagged with what stayed
  human-approved.
- `09_XPRIZE/evidencia.md` — dated, source-linked log of what shipped and when.

## 3. Verify AI is live, not a slide deck

Five Python agents run on a real schedule every morning (macOS `launchd`, logs kept):

| Time (CDMX) | Agent | What it does |
|---|---|---|
| 8:00 | Media Buyer | Pulls Meta Ads + Google Ads spend, cross-references real box-office sales (Stripe), computes true CPA, alerts if it crosses a kill threshold |
| 8:03 | Boletera Sync | Checks seat occupancy per show date against the box office API, alerts on drops |
| 8:05 | Analytics/Funnel | Impression → click → visit → checkout → purchase, flags where the leak is |
| Sun 8:10 | Media Buyer + Gemini | Weekly synthesis report |
| Sun 8:20 | Ag-15 | Flushes session decisions into a permanent, dated logbook |

You can run the read-only checks yourself against the same live APIs the agents use:
```
python3 01_Agentes/03_Media-Buyer/agent.py --check-now   # Meta + Google spend vs real CPA, no writes
python3 01_Agentes/12_Boletera/agent.py --check-now       # occupancy by show date
python3 01_Agentes/06_Analytics-BI/funnel.py               # funnel leak diagnosis
```
These need API credentials that are not published (see §4) — a judge without them can instead
read the logs already produced by the scheduled runs, linked from `evidencia.md`.

## 4. What is intentionally NOT public

- `.env`, `privado/`, API tokens, Stripe keys, ad account credentials — a small-business agency
  handling real customer payments should not publish its own keys. This is normal, not evasion.
- The founder's phone/personal identifiers are redacted from the public copy of the repo.
- If a judge needs write-level or credentialed access to verify something in §3, email
  the founder (contact in the Devpost submission) or request GCP Billing/Vertex usage screenshots,
  which are attached to the submission.

## 5. Boundaries — what a human always approves

Nothing public (a post, a press pitch, a customer-facing message beyond the WhatsApp bot's
scripted replies) and no single ad-budget change over $1,500 MXN/day happens without the
founder's explicit "go." Agents detect, diagnose, and propose continuously; only irreversible
or public actions wait on a human. See `../CLAUDE.md` §6 "Reglas de Oro" (Spanish, internal
operating rules — English summary above is accurate).
